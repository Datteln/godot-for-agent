## Why

The map-platform-plan validation layer rejects correct LLM-authored plans more often than wrong ones. In a recorded session the LLM diagnosed and fixed its one real mistake (segment endpoint y-coordinate) on the second attempt, yet still could not ship: a validator parsing bug discarded its valid entry anchor (`entry_anchor_not_found`), and a hard two-revision cap then made the situation terminal. Separate subjective design-quality checks (over-wide platforms, repeated challenge roles) block execution as if they were correctness failures. The net effect is that the LLM's output is limited by the validators' false-negative rate, not by the LLM's own competence. The same anti-pattern — a low hard ceiling plus starving the hardest task of reasoning — recurs in the worker structured-output layer: the frame-local correction limit defaults to 1 and the final structured turn runs with a zero thinking budget while ordinary turns get the effort-tier budget. (Log review later showed the primary worker-output failure is a separate specialized-schema `const`/`enum` bug — see `fix-map-worker-stage-schema-rejection`; the A+B items here are a secondary defensive floor for genuine malformation, not the primary cure.)

## What Changes

- **Remove the platform-plan hard revision cap** (`MAP_PLATFORM_PLAN_MAX_ATTEMPTS = 2`). Semantic fingerprint dedup already rejects identical resubmissions and remains the only anti-thrash mechanism for plan resubmission; distinct revised plans are no longer count-limited and fall under the general no-progress pause.
- **Demote subjective design-quality checks to advisory.** `platform_too_wide`, `challenge_roles_repeated`, and `route_too_short` are reported in `issues`/`repair_plan` but no longer empty `edit_map_batches` or block execution. Objective reachability and safety requirements remain blocking. When advisory and blocking score issues coexist, the top-level `error_code` identifies the first non-advisory issue rather than whichever issue was appended first, so retry identity, persisted failure state, and recovery guidance name the condition that actually prevents execution.
- **Fix validator input parsing.** Entry-anchor parsing accepts a flat `{x, y, role}` dict (no nested `cell` key) as valid. Defensive dictionary/array guards distinguish an absent key from a present empty collection; the `X.get(key, {}) is Dictionary` idiom is corrected so a missing required field is rejected with a typed issue rather than silently treated as present.
- **Remove the fabricated manhattan-path connectivity repair hint** (`manhattan_path` / `build_connectivity_repair_plan`), which suggests paths not validated as reachable.
- **Raise the worker structured-output correction floor and final-turn thinking budget.** Raise the production settings default for `map_worker_structured_correction_limit` to at least two and keep every explicit call path and local helper default consistent with that configured floor. When the final structured turn falls back from a configured `thinking_budget = 0` to the effort-tier budget, persist and emit the effective budget actually passed to the provider rather than the raw zero-valued configuration. (Secondary defensive floor — the primary worker-output failure is the specialized-schema `const`/`enum` bug addressed by `fix-map-worker-stage-schema-rejection`; this item only helps genuine output malformation.)
- **Keep platform validation retry accounting scoped to platform-plan tools.** Only failed platform-plan validation tools record the `validation_failure` semantic retry used by the planner exhaustion path. Failures from sibling plan-category tools (`plan_map_layout` / `plan_map_algorithms`) do not enter that platform-validation retry identity; their successful outcomes still advance the task to `write` as described below.
- **Drop the cross-scope stay-in-plan hold for non-platform-plan tools.** A successful `plan_map_layout` / `plan_map_algorithms` now advances the map task to `write` regardless of a sibling scope's pending planner workflow; the old guard that re-locked the whole task to `plan` on a sibling pending re-plan is removed (it starved write progress and re-introduced the cross-scope thrash this change targets). Stranded dead code from the refactor is cleaned up.

## Capabilities

### New Capabilities

_(none)_

### Modified Capabilities

- `platform-traversal-validation`: subjective design-quality checks become advisory; entry-anchor and field-presence parsing correctness is pinned; objective traversal and safety requirements remain blocking, and the reported primary error always names a blocking issue.
- `map-progress-recovery`: platform-plan resubmission anti-thrash is semantic-fingerprint-only (the plan-specific hard count cap is removed), and its validation-failure retry identity remains scoped to platform-plan tools; a successful non-platform-plan plan tool (`plan_map_layout`/`plan_map_algorithms`) advances to `write` without a cross-scope stay-in-plan hold; the production-configured frame-local structured-output correction floor is at least two, and the final structured turn uses and records a non-zero thinking budget derived from the effort tier.

## Impact

- **GDScript (frontend)**: `addons/ai_agent/tools/map_platform_plan_validator.gd` (`_score_level`, `_entry_anchor_from_input`, blocked_reason assembly), `addons/ai_agent/tools/map_tools.gd` (the `is Dictionary` / `is Array` default-empty guard sites, incl. coords/atlas staleness), `addons/ai_agent/tools/map_validator.gd` (`manhattan_path`, `build_connectivity_repair_plan`).
- **Python (service)**: `app/config.py` and `app/query/engine.py` (production correction-limit source and explicit call paths), `app/orchestrator/map_progress.py` (platform-only semantic retry scope, `map_platform_plan_call_error`, `MAP_PLATFORM_PLAN_MAX_ATTEMPTS`, `planning_attempts`), and `app/orchestrator/agent.py` (effective final-structured-turn thinking wiring and evidence), plus no-progress pause wiring.
- **No public API change**; runtime rejection behavior changes (fewer false-negative plan rejections, no hard count cap).
- **Out of scope** (separate changes): lightening the write-authorization gate's scope for non-jump writes (`map_write_stage_error`); consolidating the six `_append_*_protocol_errors` choreography appenders in `agent.py`.
