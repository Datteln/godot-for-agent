## Context

可见 Thought 和助手正文目前以累计文本更新权威 transcript；`TranscriptWriter` 每次更新都会发布含完整条目的 `transcript_patch`。`EventStore` 虽以 50ms 为单条流限速，但每个快照的字节数随文本增长，且慢订阅者只在固定条数队列溢出后进入重同步。Godot 客户端在 WebSocket 回调中同步投影、更新视口并请求滚动到底部。长文本因而会把重复序列化、发送和 Markdown/控件重排叠加到同一主线程路径。

`/chat` 的空闲看门狗只在客户端收到事件时续期；空闲超时会立即调用 `/chat/interrupt`。这能停止真正卡死的请求，却会在实时事件通道暂时落后、而后端仍在安全运行时错误取消 turn。历史快照和序列化 resume 已是权威恢复通道，必须成为该异常路径的优先恢复机制。

## Goals / Non-Goals

**Goals:**

- 让长流的实时网络、服务器内存和客户端每帧工作量保持有界。
- 保留现有稳定 entry ID、revision、事件序号、完整持久化 transcript 和历史快照语义。
- 在慢订阅者、临时 WebSocket 中断或前端渲染滞后时恢复展示，而不是取消健康的后端 turn。
- 让诊断能区分生产停滞、socket 交付滞后、队列背压、投影拒绝和渲染滞后。
- 让地图区域读取的 400-cell 限制在模型调用前可见或由工具安全分块处理。

**Non-Goals:**

- 不改变模型思考预算、模型供应商流协议或完整历史导出内容。
- 不保证每个 token 都独立显示；实时展示可以合并中间修订，但最终可见条目必须完整。
- 不把 WebSocket 心跳视为模型完成或模型实际进展的证明。
- 不改变正在规划的 `dependency-aware-delegation` 的依赖调度语义。

## Decisions

### 1. 权威状态保留完整快照，实时正文使用有界合并表示

服务端继续把完整累计文本写入 `Session.transcript_entries`，历史 API 也继续返回完整条目。实时协议为同一条目区分：首次可见状态/结构状态/终态使用完整 patch；增长中的 Thought 或 assistant 文本使用可验证的追加 delta，或受最大字符数约束的 latest-preview。每个实时更新仍携带 entry ID、revision 与序列身份；客户端必须能从首个完整状态和顺序 delta 重建当前文本，缺失 delta 时则请求快照重同步。

选择此方案而不是仅把 50ms 提高到较大数值，因为较低频的累计全文仍为 O(文本长度 × 更新次数) 传输。也不截断权威状态，以免历史与复制内容丢失。

### 2. 以 entry 为粒度的 latest-wins 背压

每个订阅维护独立、按 entry stream key 合并的待发送状态：尚未写入 socket 的较旧流式正文补丁由同 entry 的较新补丁替换，结构状态和终态不得被覆盖。队列同时设置条数与字节预算；达到预算时订阅转入显式 `resync_required`，停止发送旧正文，而不是默默丢序或无限等待一个大包。恢复后客户端通过现有快照游标恢复。

选择按 entry 合并，而不是全局丢弃事件，因为不同工具/条目之间的状态顺序仍须可观察，且终态不能丢失。

### 3. 接收确认与渲染按帧分离

WebSocket 客户端解析并验证连续 seq 后立即确认交付。`ChatPanel` 将可合并的流式 patch 按 entry ID 暂存，在受限帧率/时间窗口内把每个 entry 的最新 revision 投影到 Store 和 viewport；非流式状态和终态不延迟超过一个帧边界。渲染批次最多执行一次滚动请求，并保留既有 follow-mode 与视口锚点语义。

选择客户端合并而不是只依赖服务端，因为本地历史回放、短暂调度尖峰和控件重排同样可能让 Godot 主线程落后。

### 4. 超时采用“恢复优先、取消最后”状态机

活跃 turn 在没有正文流时由服务端发送小型、不可见的 `turn_keepalive`，其中只含 turn/session、阶段和最后已持久化序号。它不同于 transport heartbeat：前者表示服务端仍持有活跃 turn，后者只表示 socket 存活。客户端的请求空闲超时先执行一次有界恢复：重连、从 ack 游标重放；收到 gap/overflow 时获取历史快照并恢复订阅。恢复成功且 turn 仍活跃时，继续等待；只有恢复失败、服务端报告 turn 不存在/异常，或达到既有硬上限时才调用 `/chat/interrupt`。

选择该策略而不是永远延长空闲超时，因为真实死锁仍须被可靠终止；也不以 heartbeat 无限续期，避免把失去模型进展的请求永久悬挂。

### 5. 建立红脱敏背压观测

服务端记录实时 payload 字节数、合并次数、队列条数/字节峰值、进入重同步的原因与 socket send 耗时。客户端记录最后接收/确认/投影/渲染的 seq 与时间、每帧合并数、渲染耗时以及超时后恢复结果。日志不得记录全文、提示词或工具结果；测试可通过这些结构化数值断言系统行为。

### 6. 空正文恢复须保持一个未终结的逻辑 Thought

一次用户可见的 Thought 可以跨越多个原始模型响应尝试。每个模型调用都生成唯一的 `response_attempt_id`，并随 reasoning/text delta、流结束及其 transcript 元数据传递；`frame_id + message_index` 不能单独作为原始响应或流式 Thought 的身份。

当某次尝试只产生 reasoning 而没有可交付正文，编排器若决定立即发起空正文恢复，必须先判定该次流结束为 **provisional**：不得向前端发布该逻辑 Thought 的 `complete` patch，也不得写入 `duration_seconds`。恢复尝试在同一逻辑 Thought 下继续，保留最初 `started_at`，并把 token 计数按尝试累积或以明确的权威总数更新。只有逻辑响应最终成功、不可恢复地失败、被取消或被显式中断时，才发布唯一的终态 Thought 和最终耗时。

`TranscriptWriter` 必须验证增量的 `response_attempt_id` 是否属于当前逻辑 Thought；已结束尝试的迟到增量不得覆盖恢复尝试的内容、token 计数、状态或时长。若未来选择把恢复尝试展示为独立 Thought，必须创建新 entry，而不能把它并入一个已完成 entry。本变更采用连续展示语义，因此空正文恢复后的最终 `Thought for Xs` 从首次 Thinking 开始计算，并在最终尝试终止时一次性固化。

选择此方案而不是在前端修正显示，因为 79.33 秒等错误值已作为服务端权威 `duration_seconds` 持久化；前端没有足够的尝试边界来可靠重算。也不允许 `complete → thinking → complete` 的可见状态回退：这样会违背终态排序保证，并可能让慢客户端以过期 complete patch 覆盖恢复中的状态。

## Risks / Trade-offs

- [增量协议兼容性] → 以版本化载荷表示，保留完整 patch 接收路径；未知 delta 或 revision 缺口统一走快照恢复。
- [latest-wins 跳过中间视觉状态] → 只合并流式正文；工具、审批、错误和终态状态保持顺序且不可合并。
- [恢复增加一次网络往返] → 仅在空闲阈值触发，成功恢复后不取消 turn；继续保留硬上限。
- [批处理降低逐 token 动画感] → 设定短且可配置的显示窗口，优先保证编辑器交互性和最终一致性。
- [自动分块掩盖调用错误] → 只为明确可拼接的 map region 读取启用；响应标注分块边界和总单元数。

## Migration Plan

1. 先发布服务端/前端兼容的实时载荷与新增观测，旧客户端仍可消费完整 patch。
2. 启用 entry 级合并和客户端批处理，使用长流压测验证 payload、队列和帧耗时上限。
3. 启用恢复优先的超时路径，验证 WebSocket 断连、队列溢出与真实后端卡死三类场景。
4. 将地图范围约束纳入 schema/工具适配，并保留原始 `region_too_large` 作为无法安全分块时的结构化错误。
5. 任一阶段出现恢复错误时，关闭增量/合并特性，回退到完整 patch + 现有快照重同步；不迁移或修改既有会话历史。
6. 在启用空正文恢复前，加入跨尝试 Thought fixture；断言单个逻辑 Thought 不会在恢复开始时冻结时长，且迟到旧尝试不会覆盖恢复尝试。

## Open Questions

- 实时正文选择纯 append delta，还是以固定上限 latest-preview 兼容旧渲染器；实施前以现有 WebSocket 兼容测试决定。
- 每订阅的字节预算、流式发布间隔和前端批次窗口应从压测基线确定，而非硬编码为本变更的固定常量。
- `describe_map_region` 的自动分块是否需要对不同 map 类型施加不同深度/维度限制；先以 2D TileMap 与 legacy TileMap 覆盖为准。
- 对于非空但被策略性重试的模型响应，是否也延续同一逻辑 Thought；本变更先覆盖“空正文后立即恢复”，其他重试须显式选择连续或独立展示语义。
